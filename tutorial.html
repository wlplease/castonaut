Start Snapchain.

Follow the official read-node setup prompts. Leave the VM running while the first snapshot syncs; it can take hours.

In another terminal, repeat this check until it says READY and the endpoint is reachable:

Connect Castonaut.

Keep the node running. Open the local link in the terminal and sign in with an existing test account that has storage. A linked wallet can authorize a scoped app key without revealing a recovery phrase to this page.

npm run client -- --zone us-central1-a
The node sees your computer’s public IP in local mode. Only enter a recovery phrase on a build whose code and operator you trust.
Monitoring and cleanup commands

Use this read-only snapshot to inspect sync, disk, and container health:

npm run node:status:once -- us-central1-a
Cleanup asks you to type DELETE. It removes the VM, disk, firewall rule, and node data. Google trial details ↗
Run your own client?

The hosted site needs no setup or personal node. To run the client locally, clone the repo, run npm ci, then connect it to a node you trust:

npm run client -- --node-url https://YOUR-NODE

This opens a local web app, not a packaged desktop app. If you use your own public node, it can see your computer’s public IP.

02PROTOCOL BASICSTHE PIECES BEHIND THE WINDOW

Small pieces.
Clear responsibilities.

A / IDENTITY
⌑

Wallet-linked FID

The client checks the connected custody address against the Optimism ID Registry to find its numeric Farcaster ID (FID). A username or FID is never treated as proof of identity.

B / CUSTODY
⌑

Custody address

The Ethereum address registered to the FID. It authorizes signer changes and controls the account’s recovery path.

C / APP ACCESS
KEY+

Scoped app key

A separate Ed25519 key signs app messages. Gasless KEY_ADD is authorized by an EIP-712 custody signature and restricts message types.

D / STORAGE
▤

Storage rent

An existing FID needs protocol storage units to publish messages. This client does not register new accounts or buy storage.

E / MESSAGE
✉

Snapchain message

A signed, encoded message such as a cast, follow, or reaction. Castonaut signs it in your browser and sends it through the app service.

F / NODE ROLE
R ≠ V

Read node / validator

Your read node follows decided blocks and serves APIs. It can accept a signed message and relay it to validators; validators propose and vote on blocks.

03OPERATOR FIELD GUIDEKEEP IT HEALTHY

Good habits.
Fewer surprises.

01 / BEFORE YOU CONNECT
✓

Check readiness.

Run npm run node:check -- us-central1-a. Connect only when it reports READY and the public endpoint is reachable. Recheck later; a node can fall behind.

02 / ROUTINE CHECK
⌁

Watch the basics.

Run npm run node:status:once -- us-central1-a. Look at shard delay, free disk, and container health. Save the output when troubleshooting; a single sample is not a trend.

03 / COST CONTROL
$

Check billing, not just uptime.

Set a budget alert and inspect actual charges. Stopping a VM can stop compute charges, but attached disks and reserved IPs may still cost money. Delete resources only when you no longer need their data.

Google Cloud billing behavior ↗
04 / PROTECT YOUR DATA
▤

Don’t reset data to fix sync.

Keep the data disk mounted and check logs, network, and disk space first. Never remove Snapchain’s data directory as a routine fix; a reset discards the local database and may mean another long sync.

05 / NETWORK PRIVACY
◎

Know what is public.

Hosted node requests come from the host service; local mode connects from your computer’s public IP. This setup exposes the node endpoint over plain HTTP to the internet. Treat it as public: never send credentials through it, and don’t assume it hides your IP.

06 / WHEN SOMETHING FAILS
?

Pause before retrying.

Check readiness and recent logs first. If a signer or cast confirmation is pending, check its status before creating another key or resending. A relay response alone does not prove the cast was committed.

◇
Keep credentials out of the repo.

Never commit recovery phrases, private keys, service-account JSON, or local .env files. Treat terminal output and screenshots as public if they contain credentials or private endpoint details.

Quick recovery: what should I check?

Node says NOT READY: wait for sync, then rerun npm run node:check -- us-central1-a. Compare the shard delays over time; do not clear the database to force progress.

Endpoint is unreachable: confirm the VM is running, verify its current IP and firewall, then inspect recent logs. This setup opens the node ports publicly and does not configure HTTPS; add a TLS proxy and suitable access controls before treating it as a private service.

Disk is nearly full: pause the test and review disk use before continuing. Do not delete Snapchain data files by hand.

Signer is still pending: use the client’s check-again action and wait for the signer to appear. Don’t authorize another key just because confirmation is slow.

Cast is not visible: a submit acknowledgment only means relay acceptance. Refresh the feed or check network state before resending to avoid duplicate casts.

Done for now: stopping the VM preserves its disk and data but may leave storage/IP charges. Destroying it removes the disk and synced data too.

ACCOUNT SECURITYSCOPED APP KEY

Know what you’re authorizing.

Your custody account signs a limited authorization for a separate app key. It is a gasless message signature, not a transaction. The phrase is processed in the tab, cleared from the field, and never saved or sent to the server. Website code can read it while you enter it, so only use phrase sign-in on a site whose code and operator you trust; a linked wallet avoids exposing the phrase to the page.

  • The key is limited to social actions. Its 30-day sliding expiry can refresh with use, so an active key may stay valid; revoke it from the account’s signer controls to disable it sooner.
  • JavaScript cannot promise secure zeroization from memory. Close the page after setup and protect your device.
  • “Forget this browser” removes the local app key but does not revoke the network signer. Revoke the signer separately from the account’s signer controls.
  • Review the source and only run software you trust. Never enter a phrase into a site from an unknown developer.
05CLIENT SOURCEINCLUDE OR HIDE BY APP

Your feed.
Your source lens.

Filter by app FID when Snapchain provides it.

CAST / FID 12APP FID 123
CAST / FID 28SOURCE UNKNOWN
CAST / FID 81APP FID 123

Attribution has limits.

Find the app FID on the client’s Farcaster profile. For gasless app keys, Snapchain signer records can associate a signer with a requester FID when the requesting app uses its own FID. Older signers, missing metadata, self-requested keys, or unrecognized signers may not identify a client. Castonaut labels those casts “source unknown” and never guesses.

The source field is an aid for personal feed control, not proof of authorship or a complete audit trail.
