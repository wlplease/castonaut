01QUICKSTARTTHREE COMMANDS · ALLOW SEVERAL HOURS FOR FIRST SYNC

For builders:
run a test node.

These optional steps provision Google Compute Engine, install Snapchain on the VM, and run the client locally. A new node downloads a historical snapshot first. A first sync can take many hours, and the API may remain unavailable during snapshot restore. Check live node readiness before proceeding. Timing varies with the machine, snapshot, and network.

⌑
Before you startNode.js 22+, the Google Cloud CLI, an authenticated Google account, a project with billing enabled, and a dedicated Farcaster test account with an existing FID, storage, and linked custody wallet. Prefer that wallet’s delegated app-key signature; it is gasless and needs no Optimism transaction, ETH, or gas. Never paste your primary account’s recovery phrase into software you have not reviewed: page code can read a phrase while it is entered. Install dependencies once with npm ci.

INSTALL THE READ NODE

Run the official Snapchain bootstrap.

Opens SSH to the VM and runs Farcaster’s bootstrap script. Read the operator notice, type Yes to accept it, then enter an operator FID or username when prompted. Press Ctrl+C once after logs start. Keep the VM running while the snapshot downloads; startup can take several hours. After the installer exits, the script checks /v1/info from inside the VM. If the snapshot is still loading, check readiness later with npm run node:check -- us-central1-a.

npm run node -- us-central1-a

Verify your account and open your station.

Replace the placeholder with the public IP printed in step 1. The local dev server proxies requests to that HTTP API and enables free contest access; this tutorial does not require a Time Pass or payment wallet. Sign in with the dedicated test account from step 0 and prefer the linked-wallet option to authorize its limited app key. Know what can cost money.

Vercel Hobby can run this static client and its small serverless proxy within free usage limits. Eligible Google Cloud trial credits can cover eligible node usage without charging the payment method, but still consume the grant. Confirm your account eligibility, remaining credit, and expiry before testing; this guide cannot verify them for you. The 4-vCPU VM, 2-TB data disk, and 30-GB boot disk are estimated around $0.25/hour, about $42 for seven days, before network and IP charges. Stopping the VM stops compute charges, but the data disk still costs about $82/month until deleted. The project’s $25 monthly budget sends 50%, 80%, and 100% warning emails; it does not stop usage. Keep the account in trial status, monitor the credit, and run npm run destroy -- us-central1-a after the test if you want to stop all node charges.

!
Ready means synced and reachable.

Run npm run node:check -- us-central1-a. It checks Snapchain on the VM and the public HTTP endpoint from your computer. It exits successfully only when the maximum active-shard delay is 10 seconds or less and the public endpoint responds. A running VM or responding API alone is not ready. A valid trial grant closes at its credit limit or after 90 days, but this project’s $25 budget is an alert, not a $200 cap. Confirm account type, remaining credit, and end date in Cloud Billing before extending any run; never upgrade paid billing just to keep syncing.

02PROTOCOL BASICSTHE PIECES BEHIND THE WINDOW

Small pieces.
Clear responsibilities.

This section is for curious builders who want to understand the path from account to message.

A / IDENTITY
⌑

Wallet-linked FID

The client checks the connected custody address against the Optimism ID Registry to find its numeric Farcaster ID (FID). A username or FID is never treated as proof of identity.

B / CUSTODY
⌑

Custody address

The Ethereum address registered to the FID. It authorizes signer changes and controls the account’s recovery path.

C / APP ACCESS
KEY+

Scoped app key

A separate Ed25519 key signs app messages. Gasless KEY_ADD is authorized by an EIP-712 custody signature and restricts message types.

D / STORAGE
▤

Storage rent

An existing FID needs protocol storage units to publish messages. This client does not register new accounts or buy storage.

E / MESSAGE
✉

Snapchain message

A signed, encoded message such as a cast, follow, or reaction. Castonaut signs it in your browser and sends it through the app service.

F / NODE ROLE
R ≠ V

Read node / validator

Your read node follows decided blocks and serves APIs. It can accept a signed message and relay it to validators; validators propose and vote on blocks.

ACCOUNT SECURITYSCOPED APP KEY

Know what you’re authorizing.

Your custody account signs a limited authorization for a separate app key. It is a gasless message signature, not a transaction. The phrase is processed in the tab, cleared from the field, and never saved or sent to the server. Website code can read it while you enter it, so only use phrase sign-in on a site whose code and operator you trust; a linked wallet avoids exposing the phrase to the page.

  • The key is limited to social actions. Its 30-day sliding expiry can refresh with use, so an active key may stay valid; revoke it from the account’s signer controls to disable it sooner.
  • JavaScript cannot promise secure zeroization from memory. Close the page after setup and protect your device.
  • “Forget this browser” removes the local app key but does not revoke the network signer. Revoke the signer separately from the account’s signer controls.
  • Review the source and only run software you trust. Never enter a phrase into a site from an unknown developer.
04CLIENT SOURCEINCLUDE OR HIDE BY APP

Your feed.
Your source lens.

Castonaut can filter by the app FID associated with a cast’s signer when that attribution is available from the node.

CAST / FID 12APP FID 123
CAST / FID 28SOURCE UNKNOWN
CAST / FID 81APP FID 123

Attribution has limits.

Find the app FID on the client’s Farcaster profile. For gasless app keys, Snapchain signer records can associate a signer with a requester FID when the requesting app uses its own FID. Older signers, missing metadata, self-requested keys, or unrecognized signers may not identify a client. Castonaut labels those casts “source unknown” and never guesses.

The source field is an aid for personal feed control, not proof of authorship or a complete audit trail.
